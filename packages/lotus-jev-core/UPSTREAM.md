# Jev Ultrafast core

Source: https://github.com/browser-use/jev-ultrafast, commit `1231850a0bf1a0c0341fe408ef1668dbbfdfac46`, MIT (LICENSE retained).

The five core files come from Donovan's computer-use skill at `jev-computer-use` commit `171b1042207df640d965217badc206412dedf7b5`. That adaptation adds observed checkbox labels, input freshness, field context, completion audits, nested scrolling and uncertainty detection. Package version 0.1.0 includes the subsequent Lotus adaptations from LotusOS commit `bbc121fe1a36580ef7f0f06a0f9022a4c374c02a`. The wheel contains only this core, its DOM snapshot script and attribution; it excludes the upstream application, inspector and browser launcher. It has no third-party runtime dependencies.

Lotus changes: provider IO uses an injected credential-free relay; field text uses God and missing values request human input; the optional LLM recovery planner is removed; Agent accepts a lifecycle-controlled Browser; unsupported or uncertain operations return to the host for automatic recovery or actual human-input requirements. Both operation and target confidence participate in recovery; legitimate waits are excluded from cycling detection. Disabled controls remain observation evidence with safe current values, checked state and read-only state. Link actions expose their absolute destination through the model action space. New tabs and read/report completion are supported by the host instead of prompting delegation. Text insertion checks that focus still belongs to the observed node after clicking and keyboard events. The host can use text guidance and Browser Use recovery while retaining Jev as its primary driver. The host owns the initial page, private Chromium, deadlines, control epochs and final answer extraction.

To update: compare the pinned upstream and skill sources, reapply these changes, update both revisions and this package's version, then run the package tests and consuming host's Jev relay/lifecycle checks. Build a new release wheel and update the host's version and digest pin. Do not replace the host's private browser with upstream's shared browser launcher.

`Browser.read_document()` supplies bounded rendered-document text and links for host-owned final answers, including offscreen content. This read-only evidence operation is separate from viewport observations used by the decision loop.
